# 03 方向决策与非目标

## ADR-01：质量优先，性能按触发门排期

选择：**在现有索引与JDT之上补小型证据导航层，不更换底座。**

| 路线 | 收益假设 | 成本/风险 | 决策 |
|---|---|---|---|
| A 证据质量与交互闭环 | 改善文件内错选、关键片段不到达、预算内冗余 | 少量接口变化，效果需实测 | 主线 |
| B 持续SQL/调度/GC微优化 | 继续减少单次延迟 | 容易进入低边际收益；改变已验证生命周期 | 只在真实慢点触发 |
| C 更换JDT/自建resolver/大图 | 理论上统一更深语义 | 个人维护面大，MAC16没有建立触发证据 | 不做 |
| D 重启embedding | 改善无词汇重叠的发现 | 用户已否决；重复实验与第二索引成本 | 本路线禁止 |

## 三种“准确性”分别度量

1. **绑定正确**：引用指向哪个声明、范围是否精确、是否存在歧义。JDT或静态事实验证，不能由文本相似度/分数证明。
2. **任务相关**：找到了正确类但是否找到正确方法、配置和测试。需要独立任务标签，不能用K32替代。
3. **任务完成**：给出的证据是否真正进入请求、答案/补丁是否通过冻结规则。需要真实Agent控制和独立oracle。

索引稳定性保护三者的前提，但不自动提升任何一种。当前更强证据指向第2和第3种缺口 [S06–S09]。

## 预期体验

用户问“为什么取消订单后库存有时没恢复”：先静态query找到OrderService；outline对比cancel、reserve、release而非盯住create；evidence读取cancel的条件和调用点；必要时展开StockLedger.release；若接口多实现，显示候选与条件，按需JDT确认静态目标。工具不宣称静态图已经证明线上并发原因。

## 边界

Java源码是核心；XML/properties/注解是Java工程关联证据，不构成多语言扩张。默认5个MCP工具不增加；允许现有java_symbol增加outline操作。只读工具不改Java项目，不自动写业务补丁。

一次只保留一种默认检索/选择实现。试验代码应能删除，最多一个正在评估的行为开关；通过以后合并一条主线，不保留新旧planner永久共存。

## 优先级

| 顺序 | 做什么 | 不做什么 |
|---|---|---|
| 0 | 确认线上/源码/实测身份、时间合同，校准测量边界 | 盲重装、改TCC、重跑所有canary |
| 1 | attribution与最终消息验证 | 再造benchmark平台或改gold |
| 2 | 按需文件outline、Java evidence | 默认整文件、全图、每轮地图 |
| 3 | 有失败证据的局部关系/选择/词法改进 | 扩maxFiles或调权直到熟悉题绿 |
| 4 | 有触发才补精确绑定/冷启动复用 | 全编译器替换、永久预热所有仓 |
| 5 | 一次真实Agent配对与删减 | 无限模型/提示重试 |

## 停止条件

Q00–Q04完成后先检查是否已够日常使用。若真实任务无质量提升、无总成本下降，则撤销非必要展示/额外字段，保留正确性修复与测量能力。若最多两个同预算候选试验仍无新可解释收益，暂停该子方向。

“没有显著新收益”是合法结果。个人项目不需要一直改造；稳定、低维护且能解释限制的版本本身可以是最终产品。
