# 15 面向日常Java开发的具体优先级

## 第一条：接口/行为定位

输入是路由、中文需求、错误信息或不完整类名。先用已有词法/注释/框架key搜索；同文件候选接近时调用outline比较声明；定位后evidence读关键分支和调用点。必要时追一跳service/mapper。只要靠这条短链能解决问题，不先启动JDT或读取整个模块。

验收不是“找到Controller文件”，而是找到正确handler和关键分支。候选正确、方法错误归Q03；方法正确、分支缺失归Q04/Q07；完全无词汇交集归Q06的宿主显式terms，不触发embedding。

## 第二条：字段/接口影响

DTO字段和数据库column不是同一实体。需要分别提供字段声明、显式访问点、序列化/映射声明、XML resultMap或statement及相关测试证据。JDT用于准确Java引用；字面量配置与XML通过已存在结构/文本路径补充，不能要求JDT覆盖所有资源。

对接口引用，应区分“声明契约的使用者”“实现类的使用者”“override-family集合”。返回一个有范围的候选集合可能比伪造唯一目标更准确。Spring运行时profile/代理未知时不做确定性装配结论。

## 第三条：异常/状态排查

先从栈帧/错误码定位精确方法及邻近条件，而不是全仓相似文件。长方法需要围绕明确位置取片段，不能只展示头尾。证据足够后，宿主继续编译/测试；工具不从静态@Transactional注解推断数据库事务实际行为。

## 暂不排入主线的事项

完整污点分析、全程序points-to、安全扫描、架构规则DSL、自动重构、外部库全量反编译、泛化IDE编辑器均不做。若未来每天都卡在外部依赖API版本，可设计一个“准确版本依赖符号读取”小ADR，但本轮没有证据触发。

## 给使用者的简短路由说明（待Q10验证后才安装）

```text
已知符号/位置：直接java_symbol position/references或java_impact。
未知入口：static query；定位到文件但不确定方法时再outline。
已选方法要看逻辑：evidence；不够时用原生read读取明确范围。
只有需要编译器绑定时才用JDT；不需要每次先status/start。
PARTIAL/AMBIGUOUS是继续定位或缩范围的提示，不是“没有相关代码”。
```

这段guidance必须作为两臂控制因素之一记录，不能给treatment额外答案提示。用户全局AGENTS文件不自动改写。[S06]曾生成guidance diff而未安装，当前实际指导语需Q00核对。

## 维护预算

首轮只要求一个单文件outline和一个扩展evidence路径。每多一类framework关系都需要一个重复失败案例和一个可长期维护的验证。新开关若只用于对照，试验结束后删除一边；没有必要为个人使用保留通用Provider接口、复杂插件系统或多后端路由。
