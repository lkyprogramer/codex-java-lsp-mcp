# 02 业界对照：借机制，不复制产品边界

核查日期2026-11-05；外部来源见[13](13-sources.md)。以下为设计机制对照，不是性能排名；本轮没有安装各竞品或运行同一Java测试集。

| 项目/研究 | 可核实的相关机制 | 对本项目的决策 |
|---|---|---|
| Bifrost | 目标定向usage与全仓图是不同工作负载；proof、扫描completion、输出截断分列 | 借鉴明确目标/范围/证据，不引入Rust重写或通用查询语言 [E01] |
| Bifrost新name resolution | 内容级事实与query上下文分开；文档仍把Java/Scala新引擎列为trial/cutover | 不能说它已证明本项目应替换JDT；ILV2已有快照基础，无需照搬stack graph [E02] |
| UsageBench Java | 11个Java用例中两者都发现要求目标；strict差异主要是返回范围和override-family分组 | 增加“目标身份/标识符范围/家族语义”三维验收，不把JDT broad range直接判绑定失败 [E03] |
| Serena | 符号概览、定位、使用点的渐进操作；JetBrains后端依赖已打开且根一致的IDE项目 | 作为小规模对照；不加入IDE强依赖、多语言/编辑/调试功能 [E04] |
| codebase-memory-mcp | 本地持久结构图、AST和类型解析，较广语言覆盖 | 可学紧凑结构查询；语言数和宣传token倍率不构成本项目验收目标 [E05] |
| Graphify | 代码图的提取/推断来源标签，代码与非代码内容联结 | 借来源解释；不建社区检测、可视化、PDF/视频或通用知识平台 [E06] |
| Aider repo map | 用符号签名与图相关性在预算内选上下文 | 做局部按需outline，不把全仓地图每轮硬塞给宿主 [E07] |
| scip-java | Java编译器插件输出逐文件索引，绑定实际build环境 | 暂不实施；只有反复classpath/生成代码错误且JDT不能满足时再单独ADR [E08] |
| RepoNav | 保持底层retrieval不变，重组为文件内可继续导航的候选 | 借后检索展示假设，而非引入论文的dense底座；验证只在Python，Java收益未证实 [P01] |

## 最有用的研究结论

RepoNav的核心可移植假设是：到达正确文件后，Agent仍可能选错同文件的函数；给可展开的结构和替代候选，比单纯提供更多片段更值得测试。论文使用既有dense检索，但后检索组织与dense本身不是同一因素。本项目可以固定已有BM25/结构候选，只测试outline及候选组织，不需要重新开启embedding。

UsageBench提醒我们不要把工具输出口径差异误判为语言理解失败。例如引用返回调用表达式范围和标识符范围是两种精度；接口家族引用也不等同于单声明引用。它只有11个Java开发案例，不足以宣布Bifrost总体优于JDT，更不证明速度或内存优势。

## 三条不该复制的路线

**全编译器替换。** 泛型/重载/作用域/模块/动态分派的完整实现会显著扩大个人维护面。先用精确位置与现有JDT验证少数疑难点。

**多语言通用图。** 多语言IR、图查询语言和企业跨仓服务能服务其他产品目标，但不是本项目的目标。现有SQLite/Tree-sitter事实足够支持窄导航试验。

**不可证伪的context万能封装。** 不复活旧java_context，工具端不自动反复规划、不嵌入LLM，不承担宿主的长期记忆。

## 对照实验只保留真正必要的两个

第一，产品当前版本与“同候选+outline/evidence”版本配对，隔离接口和交付贡献。第二，资源允许时选择Serena或一个结构检索工具作外部参考，固定Java仓库、任务、模型、原生工具和预算；外部基线没有正确安装时记UNAVAILABLE，不记0分。无论外部工具结果如何，本项目优先验收自己的净收益。
