## Interfaces

新增 receiptForSerializedRequest({body: string, workspaceId: string, contentManifestId: string, units: ReceiptUnitInput[]}): Receipt；body为最终JSON字符串，units对应05/11规范。新增 judgeCompletion({exitCode:number|null, receipt:CompletionReceipt|null, expectedRunId:string, expectedOracleHash:string}): "COMPLETE"|"INCOMPLETE"；CompletionReceipt={runId,oracleHash,normalReturn:true}。

公共预算、view/proof和状态合同继承[05](../docs/05-contracts.md)；所有测试变量如report/summary由本卡实际fixture/函数结果生成，不能硬编码成预期答案。纯断言示例在现有Node test包中落地，assert使用`node:assert/strict`。

## RED / 控制断言

```ts
assert.equal(judgeCompletion({ exitCode: 0, receipt: null,
  expectedRunId: "run-a", expectedOracleHash: "h" }), "INCOMPLETE");
assert.equal(judgeCompletion({ exitCode: 0,
  receipt: { runId: "run-a", oracleHash: "h", normalReturn: true },
  expectedRunId: "run-a", expectedOracleHash: "h" }), "COMPLETE");
assert.equal(judgeCompletion({ exitCode: 1,
  receipt: { runId: "run-a", oracleHash: "h", normalReturn: true },
  expectedRunId: "run-a", expectedOracleHash: "h" }), "INCOMPLETE");
```

对本来正确的既有行为，记录现有测试与补充边界，不修改代码强造RED。对新行为，测试应因缺失行为失败，而不是因为路径拼写/依赖装载失败。
