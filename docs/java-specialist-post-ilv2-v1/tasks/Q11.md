# Q11 · 受影响工程门与候选资格

**阶段：** P4  
**依赖：** Q10  
**实施属性：** 主线任务；模型/生产调用仍受独立授权

## 目标与边界

让质量改进不损坏ILV2已验证的稳定性，同时不重开无关验收。

## 文件

现有K contract overlay、对应snapshot/view/deadline/工具测试；docs/post-ilv2/acceptance.md和candidate身份清单。

文件路径按本包固定SHA核查或明确标为拟新增。执行前确认文件存在；旧文件改名时记录映射并跟随真实调用链，不创建重复模块。共享schema与symbol.ts接线由单一集成者合入。

## Interfaces

输出engineeringEligibility、benefit、deployAuthorization三个独立字段；checks按same-build raw绑定。没有部署授权也可ENGINEERING_ELIGIBLE。

公共预算、view/proof和状态合同继承[05](../docs/05-contracts.md)；所有测试变量如report/summary由本卡实际fixture/函数结果生成，不能硬编码成预期答案。纯断言示例在现有Node test包中落地，assert使用`node:assert/strict`。

## RED / 控制断言

```ts
assert.equal(decision.engineeringEligibility,"ENGINEERING_ELIGIBLE");
assert.equal(decision.benefit,"UNMEASURED");
assert.equal(decision.deployAuthorized,false);
assert.notEqual(decision.state,"DEPLOYED");
```

对本来正确的既有行为，记录现有测试与补充边界，不修改代码强造RED。对新行为，测试应因缺失行为失败，而不是因为路径拼写/依赖装载失败。
