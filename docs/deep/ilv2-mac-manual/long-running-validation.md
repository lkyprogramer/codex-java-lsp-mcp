# Mac 长时间测试验证规范

适用于预计超过 5 分钟、包含多道工程门或需要索引冷启动的验收。测试与验收判定由本机脚本完成。会话在确认启动后可以结束本轮，结果由终态交接。

## 1. 启动前

- 在登记过的运行根下创建本次目录，绑定 Git SHA、候选构建、运行环境和命令顺序。写明通过条件、允许的跳过项、阶段超时、失败后停止还是继续。会用到已有构建时记录 build-stamp 文件的 SHA-256。
- 把命令和可确定的校验写进一个脚本。每阶段独立记录 stdout/stderr、退出码和起止时间。工程门要同时检查退出码和约定指标，例如 TAP、跳过清单、schema 大小。
- 用能独立于会话存活的本机后台进程或任务执行器启动，重定向标准输入和输出。确认运行目录、进程身份和首条状态已落盘。需要定时唤醒时按第 3 节登记，随后结束当前轮次。仅有 PTY 会话 ID 时，先确认宿主会保留子进程，再依赖这种方式交接。

## 2. 状态与进度

| 文件 | 写入内容 | 检查者读取方式 |
|---|---|---|
| `status.json` | run ID、Git SHA、当前阶段、阶段起点、最近心跳、执行器身份、阶段时限 | 未见终态时读取，用于判断当前阶段和执行器状态 |
| `events.jsonl` | 按时间追加阶段开始、结束、退出码及实际完成数 | 排查停滞或需要进度明细时读取 |
| `<stage>.log` | 各阶段原始输出 | 失败时读取对应错误段 |
| `result.json` | 终态、失败阶段、未运行阶段、验收计数、原始产物路径与 SHA-256 | 结束后生成报告并核对交付 |

`status.json` 和 `result.json` 先写临时文件再替换。可用 TAP 计数或已落盘的任务数表示真实进度。没有可靠分母时只报告阶段和耗时。心跳证明执行器存活，不能证明子命令仍在推进。阶段超时由执行器处理，只终止本次进程组。

| 观察结果 | 处理 |
|---|---|
| `RUNNING`，执行器仍有效且阶段未超时 | 不读取全量日志，结束本次检查 |
| `PASS` | 核对候选身份、退出码和指标，交付验收报告 |
| `FAIL` 或 `TIMEOUT` | 保留首次失败的原始报错，后续未执行的门记为 `NOT_RUN` |
| 执行器已退出，缺少终态 | 记为 `INCOMPLETE`，先核对退出码和已有产物 |

恢复时先核对同一候选的阶段记录。只有确认某阶段未完成且原任务允许继续时，才执行剩余工作。验收通过、生成报告、提交和推送分别按本次任务的授权执行。

## 3. 定时唤醒当前会话与结束

- 需要 Codex 自动接续验收时，创建绑定到当前会话的内置定时任务（Heartbeat），默认每 15 分钟唤醒一次。任务提示词写明 run ID、运行目录的绝对路径、最晚检查时间和终态处理方式。确认后台脚本和定时任务均已启动后结束当前轮次。[OpenAI 的 Codex Heartbeat 示例](https://developers.openai.com/cookbook/examples/agents_sdk/agent_improvement_loop)
- 每次唤醒先检查 `result.json`。尚未生成时只读 `status.json`。若执行器仍有效且阶段未超时，结束本轮，等下一次触发。只有状态过旧、缺失或身份不一致时才进一步检查执行器和当前阶段日志。每次唤醒只检查一次，跳过已完成阶段。
- 终态时汇报结果并暂停本次 Heartbeat。到达最晚检查时间仍无终态时，汇报最后状态和缺少的证据，并暂停本次 Heartbeat。脚本按自己的阶段时限处理超时。
- 每次 Heartbeat 唤醒都会启动一个模型轮次。只需要完成通知时，可以让本机脚本在终态通知一次，定时检查和通知均可由本机脚本完成。

P6 全量工程门在 Mac 上用了约 35 分钟，其中 `npm test` 约 29 分钟。P6 脚本仅作为工程门串联示例，涵盖阶段退出码、D14 跳过白名单、stdio smoke 和两种 schema 字节门槛。复用前须按本规范补齐阶段超时、周期心跳和异常终态写入。[P6 工程门结果](../../post-ilv2/results/P6-GATES.json)
