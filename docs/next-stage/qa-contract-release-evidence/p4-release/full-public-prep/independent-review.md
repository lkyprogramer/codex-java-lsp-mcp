## Findings and resolution (locations below refer to the original reviewed version)

1. **P2: repair judge is not bound to the actual candidate tree.** `score-full-public.mjs:66-72` checks that a candidate directory and JSON artifact exist, then checks only task_id, mode and validated_success, and compares the run's self-carried wrapper state with the original outcome helper. It does not compare the original judge's `candidate_tree` file hashes with the current candidate or bind the artifact SHA. A stale successful judge for the same task can therefore be associated with a different current candidate and still pass this adapter. The frozen judge already supplies `candidate_tree` and `frozen_test_sha256` (`baseline-kit/harness/repairs.py:49`); minimally validate those against the actual candidate and original test, preserve the judge artifact SHA and candidate file identity, and reject stale/mismatched success receipts. Add a small offline negative case for same task + different candidate bytes. This reduces evidence misassociation risk; it does not claim cryptographic proof of model execution.

2. **P2: ordinary failed QA and rejected/blocked repair rows abort the complete report instead of remaining in the denominator.** `score-full-public.mjs:66` unconditionally requires every repair to have a frozen-judge.json before any score output is created. The original `scripts/eval-repair-adapter.mjs:294-321` returns REJECTED_MISSING_ALLOWED_FILE, REJECTED_DISALLOWED_EDIT or REJECTED_UNSAFE_PATH before invoking Python, without such an artifact. `scoreRunOutcome` legitimately treats these rejections as MEASURED false; BLOCKED_SETUP/BLOCKED_ENV can also lack the artifact and remain UNMEASURED. Likewise new adapter lines61-64 require every COMPLETED QA to have a SUBMITTED receipt. Original `evaluate-java-task.mjs:646-651` maps INVALID_SUBMISSION, MODEL_STOP and MAX_ROUNDS to COMPLETED, while `run-agent-trace-live.mjs:706,761,768` legitimately returns those with NO_SUBMISSION. Thus both an unsuccessful agent edit and an ordinary failed submission can prevent all72 scheduled rows and completed QA from being scored. Preserve these outcomes using original semantics and retain every planned key; no-receipt QA must receive no answer credit (null answer, no normalization), and pre-judge repair rejections must not require nonexistent artifacts. Never turn missing/blocked rows into measured success. Success/actual-judge claims still require strong artifact/candidate binding. Add negative QA/failed/blocked/missing cases separate from the offline empty-pack demonstration.
